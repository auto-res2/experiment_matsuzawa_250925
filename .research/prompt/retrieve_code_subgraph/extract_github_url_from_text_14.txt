# Paper Outline
GBA is designed to keep the global batch size (actual gradient aggregation size) consistent when switching between synchronous and asynchronous training. It is implemented on a Parameter Server (PS) architecture using a token-control mechanism. This mechanism employs a data list for batches, a token list (containing global step indicators for each batch), and a gradient buffer. Workers pull parameters, a batch, and a token, compute gradients, and send the gradient with its token back to the PS. Fast workers continue processing without waiting. When the gradient buffer accumulates a predefined number (M) of gradients, they are aggregated and applied. A staleness decay strategy (f(τ(m,k),k)) is applied, where gradients with staleness exceeding a threshold (ι) are excluded from aggregation. The convergence analysis of GBA demonstrates comparable properties to synchronous training, particularly for sparse recommendation models where embedding parameters are less sensitive to staleness.
