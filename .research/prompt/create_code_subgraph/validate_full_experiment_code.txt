# Experimental Design

## Experiment Strategy
Experiment 1 – Single-frame Accuracy + Latency Benchmark
-------------------------------------------------------
Goal: Show that FLASH-TTA reaches or exceeds SOTA corruption robustness while keeping true single-pass latency.

Setup
1. Datasets: CIFAR-10-C/100-C, ImageNet-C (all severities).
2. Models: ResNet-50, MobileNet-V3-S, DeiT-Small.
3. Methods compared: Source, BN-adapt, Tent, EATA, CoTTA, STAMP, FLASH-TTA (+ four ablations: no-cov, EMA, two-pass, Fourier-only training).
4. Hardware: single NVIDIA A100; measure latency with Nvidia Nsight-Systems (CUDA event timing, batch size = 1) and peak memory from nvidia-smi.

Procedure
• Evaluate each checkpoint once without adaptation (warm-up 50 images) to cache kernels.
• For adaptive baselines run prescribed adaptation loop; for FLASH-TTA run standard forward only.
• Record: top-1 error/Δpp from Source, Expected Calibration Error (ECE), wall-clock time per image, GPU memory.

Expected Results
• FLASH-TTA ≥ STAMP (≈ –0.5 pp top-1) and beats all others by 1-6 pp.
• Latency: FLASH-TTA within +5 % of Source, ≈ ×2 faster than STAMP, ×10–12 faster than Tent/EATA.
• Ablations: removing covariance or GRU each hurts 0.8–1.3 pp, proving their contribution; two-pass variant doubles latency with no accuracy gain.

Demonstrates
Accuracy/speed trade-off, proves “same-pass” adaptation works and that covariance+GRU are critical.


Experiment 2 – High-FPS Streaming Shift Test
-------------------------------------------
Goal: Validate continual, latency-free adaptation and drift-prevention over very long video streams.

Setup
1. Stream: 180 k frames from BDD-100k ordered day→dusk→night; injected Dirichlet(0.05) corruption drift at 256 fps.
2. Hardware: A100 for fair speed; synthetic 256 fps enqueue ensures compute-bound regime.
3. Metrics per 1 k-frame window: top-1 error, error drift (|err_t – err_0|), average entropy, catastrophic collapse events.
4. Methods: Tent, EATA, STAMP, FLASH-TTA (+ FLASH-TTA w/o safeguard).

Procedure
• Feed RGB frames sequentially; methods update online only (no look-ahead). • Log hidden-state Mahalanobis distance & safeguard triggers for FLASH-TTA.
• Repeat three random corruption schedules for statistical confidence.

Expected Results
• FLASH-TTA keeps error drift < 0.3 pp over 200 k frames; Tent drifts > 6 pp, STAMP ≈ 0.7 pp.
• Zero collapse events for FLASH-TTA; w/o safeguard shows 2–3 collapses → validates freeze mechanism.
• Throughput ≥ 260 fps on A100 (higher than stream rate), confirming no hidden latency spikes.

Demonstrates
Real-time continual adaptation strength, stability of density-tracker, and robustness to rapid distribution changes.


Experiment 3 – INT8 Edge Deployment Study
----------------------------------------
Goal: Exhibit memory, energy and calibration benefits under ultra-low precision.

Setup
1. Quantise FLASH-TTA and STAMP with TensorRT/QAT: stats & GRU int8, Δ-heads fp16.
2. Devices: Jetson Nano (Max-Q) and emulated ESP32-S3 (with TVM autotuned kernels); compile with explicit fused-BN update CUDA kernel.
3. Workload: ImageNet-C inference @ 30 fps for 10 min.
4. Tools: onboard INA3221 current sensors (Nano) for energy, cycle-accurate simulator for ESP32.

Procedure
• Run each method for identical wall-clock time.
• Capture: average FPS, joules/frame, peak RAM, ECE.

Expected Results
• FLASH-TTA int8 adds <0.2 pp error over fp32, still beats STAMP int8 by ≈0.5 pp.
• Energy: 0.34 J/frame (-18 % vs STAMP, ‑85 % vs Tent). • Extra RAM: +0.22 MB (STAMP +1.8 MB, Tent +15 MB).
• FPS: 165 (FLASH-TTA) vs 82 (STAMP) on Nano; ESP32 reaches real-time 18 fps whereas others <10 fps.

Demonstrates
Practical viability for embedded/edge, confirms low-precision design retains accuracy and superior efficiency.

EXPERIMENT 2  –  High-FPS Streaming Shift Test
────────────────────────────────────────────────────────────────────────
Goal
    Evaluate stability and drift resistance during 256 fps continual
    inference on a realistic day→night driving stream.

1. Stream & corruption scheduler
    • Base sequence: BDD-100k video frames  (180 000 frames, 1280×720,
      30 Hz) ordered chronologically from a single 2 h journey
      containing clear-day, dusk, night.
    • Frames are upsampled to 256 fps by duplication to create a
      compute-bound scenario.
    • Online corruption π_t is sampled from Dirichlet(0.05) over the 15
      ImageNet-C corruption types; severity s_t∈Uniform{1,5}.  Corruption
      parameters change every frame.
    • Three independent schedules (seeds 0-2).

2. Pre-processing
    Resize shorter-side→256, centre-crop224, convert to RGB, normalise as
    in ImageNet.  Streaming loader uses PyAV with 8-frame prefetch.

3. Methods compared
    Tent, EATA, STAMP, FLASH-TTA, FLASH-TTA-no-safeguard.

4. Metrics (per 1000-frame window)
    • Top-1 Error
    • Error Drift   Δerr_t = |err_t – err_0|
    • Average softmax entropy
    • Collapse count  (entropy<0.05 for >128 consecutive frames)
    • Throughput (fps)  – derived from CUDA events

5. Seeds, selection, duration
    One training seed (ImageNet weights) + three corruption seeds.
    Total simulated time  ≈ 11.7 min per run (180 k / 256).

6. Robustness checks
    • Sudden camera blackout  (insert 50 black frames at t=60 k).
    • OOD weather insert: ACDC-snow clip 2000 frames at t=120 k.

7. Hyper-parameter monitored online
    • Mahalanobis distance of GRU hidden vs running Gaussian model.
      Threshold δ=5.0 (tuned in Exp-1 grid); freeze duration N_freeze=8.

8. Example streaming loop (simplified)
    h=None
    for frame in stream:
        x = transform(frame).unsqueeze(0).cuda();
        start.record();
        y_pred, h = flash_tta(x, h)
        end.record(); torch.cuda.synchronize()
        if freeze_flag: h = h_prev  # no GRU update

9. Expected results (to be verified)
    • FLASH-TTA maintains <0.3 pp drift across 200 k frames.
    • 0 collapse events; no-safeguard variant triggers 2-3 collapses.
    • Effective fps ≥260 on A100, proving no hidden overhead.

EXPERIMENT 3  –  INT8 Edge Deployment Study
────────────────────────────────────────────────────────────────────────
Goal
    Demonstrate memory, energy and calibration gains of the INT8 design
    on resource-constrained hardware.

1. Hardware & toolchain
    a) NVIDIA Jetson Nano 4 GB, JetPack 5.1, TensorRT 8.6.
    b) ESP32-S3 (Xtensa LX7 @ 240 MHz) simulated with Renode + TVM 0.12
       micro-autotuner (CMSIS-NN back-end).

2. Quantisation procedure
    • 256-image calibration subset from ImageNet val (one per class).
    • Fake-quant QAT for GRU & stats (symmetric INT8 per-tensor), Δ-heads
      kept in FP16.  BN + fused-Δ CUDA kernel re-written with int8 input
      and fp16 accumulation to keep accuracy.

3. Workload & dataset
    ImageNet-C  (all corruptions, severity=3)  streamed at 30 fps for
    10 min (18 000 images).  Frames decoded on host and copied via
    zeromq to Nano / simulator.

4. Metrics
    • FPS  (Nano: averaged over 18 k images, ESP32: cycles→fps)
    • Energy / frame  (Nano: INA3221 @ 30 Hz, subtract idle; ESP32: MCU-
      cycle count × 0.6 nJ)
    • Top-1 Error  &  ECE
    • Peak RAM usage  (tegrastats / simulator logs)

5. Baselines
    • STAMP-INT8 (identical QAT recipe)
    • Tent/EATA not considered – require back-prop memory which does not
      fit into 4 GB Nano nor ESP32.

6. Seeds
    Two calibration seeds (random 256-image subset), report mean.

7. Example Nano deployment script
    import tensorrt as trt, pycuda.driver as cuda
    # build engine with INT8 calibrator, then
    for img in stream:
        cuda.memcpy_htod_async(d_input, img, stream)
        context.execute_async_v2(bindings, stream.handle)
        cuda.memcpy_dtoh_async(out, d_output, stream)
        stream.synchronize()

8. Expected results (to be verified)
    • FLASH-TTA-INT8: 165 fps @ 0.34 J/frame on Nano; 18 fps on ESP32.
    • Error +0.2 pp vs FP32; still 0.5 pp better than STAMP-INT8.
    • Peak RAM +0.22 MB over source; STAMP +1.8 MB.
