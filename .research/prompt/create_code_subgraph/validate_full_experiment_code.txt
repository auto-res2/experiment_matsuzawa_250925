# Experimental Design

## Experiment Strategy
Experiment: Dynamic-Shift Stress Test on ShiftTrack-ImageNet

Goal
Measure, in a single controlled run, (1) accuracy under continuously drifting corruptions, (2) adaptation lag, and (3) computational/energy cost of CurvTrack-TTA compared with state-of-the-art one-step TTA baselines.

Equipment
• 1× NVIDIA A100 80 GB (for reproducible research-lab numbers).
• 1× Jetson-Orin-NX dev-kit (to replicate edge setting, optional second phase).
• Power meter attached to GPU/DC rail for energy.

Protocol
1. Models
   a. ResNet-50 (BatchNorm), ConvNeXt-T (GroupNorm), ViT-B/16 (LayerNorm).
   b. All models pre-trained on ImageNet-1K, frozen except normalisation and optional affine parameters, identical to prior work.

2. Adaptors
   ① CurvTrack-TTA (ours).
   ② NG-TENT, Tent-3-step, EATA-1-step, FISHr (diag), CoTTA.
   ③ Static (no adaptation) upper/lower bounds.
   Identical hyper-parameters as published; only batch size B = 32 for all.

3. Stream
   • ShiftTrack-ImageNet (authors’ release): 260 k images.
     – Corruption type changes every 5 k frames.
     – Severity follows sine curve (period 20 k) from level 1→5→1.
     – FPS simulated at η = 1 (real-time) by issuing next batch every 33 ms wall-clock; optimiser must finish before deadline, else skipped.

4. Measurements (logged continuously)
   a. Online top-1 accuracy per image.
   b. Time-to-80-%-recovery after each corruption switch.
   c. Mean latency per image (ms) and deadline-miss rate.
   d. Energy per image (nJ) on A100 and Orin.
   e. Peak GPU memory and parameter update traffic (MB/s).

5. Termination
   • Run terminates after single pass of stream (≈2 h).  No replays—mirrors deployment.

6. Analysis
   • Plot accuracy vs. frame index; overlay baselines.
   • Compute adaptation-lag AUC (lower is better).
   • Scatter-plot accuracy vs. energy to visualise Pareto frontier.

Expected Outcome
• CurvTrack’s accuracy curve quickly rebounds after each drift, staying ~4–7 mCE ahead of best baseline; average time-to-80-%-recovery shrinks ≈5× (≈90 vs. ≥430 frames).
• Deadline misses <1 % at 60 FPS, whereas multi-step baselines miss >30 %.
• Energy: CurvTrack ≈1.3× static inference, 40 % below next-best adaptive method due to quantised updates and no backprop.
• Memory stable (<180 MB extra) thanks to block-low-rank storage; others >1 GB when keeping full gradients.

Demonstration
These results show, from three perspectives—robustness (higher accuracy), responsiveness (shorter lag), and efficiency (latency/energy/memory)—that curvature-aware, backprop-free CurvTrack realises the promised “natural gradient on a budget,” succeeding where prior diagonal or multi-backward methods fail under realistic, continuously evolving shifts.

## Experiment Details
────────────────────────────────────────────────────────────────
Dynamic-Shift Stress Test on ShiftTrack-ImageNet
────────────────────────────────────────────────────────────────
0. Rationale
   CurvTrack-TTA is designed for real-time test-time adaptation (TTA) under *continuously* drifting data.  A single long stream makes it possible to evaluate (i) robustness to evolving shifts, (ii) adaptation lag, and (iii) computational / energetic efficiency – three axes that previous, static-snapshot protocols could not probe jointly.

1. Models (frozen except where noted)
   • ResNet-50  (BatchNorm, 25.6 M params)
   • ConvNeXt-Tiny (GroupNorm, 28.6 M params)
   • ViT-B/16     (LayerNorm, 86.6 M params)
   All weights are ImageNet-1K pretrained from public checkpoints (torchvision-2023-08).  Only affine parameters of normalisation layers and per-block Fisher statistics are updated on-stream.  Mixed-precision (bfloat16 activations, fp32 master weights) is enabled throughout.

   Baseline adaptors applied *on the same backbones*:
     – Static (no adaptation)
     – Tent-3-step        (Wang et al. 2021, lr=1e-3, 3 gradient steps per batch)
     – EATA-1-step        (Wang et al. 2022, lr=1e-3, λ_ent=0.3)
     – NG-TENT            (Schneider 2023, fixed diagonal Fisher)
     – FISHr (diag)       (Nguyen 2023, one backward pass)
     – CoTTA              (Zhang 2022, EMA+augment)

2. Dataset / Stream
   ShiftTrack-ImageNet-v1.0 (authors’ release)
     – 260 000 RGB images @224² cropped from ImageNet-1K validation set plus corruption generator.
     – Corruption schedule: every 5 000 frames corruption type ∈ {fog, shot-noise … 15 total} is swapped.  Severity follows s(t)=2.5+2.5·sin(2πt/20 000)⇒levels 1↔5.
   Frame rate η = 1 ⇒ new mini-batch (32 images) arrives every 33 ms.  If adaptor has not produced logits in time, the predictions of plain forward pass are inserted and a *deadline-miss* is recorded.

3. Pre-processing
   • Decode → uint8 tensor → resize shorter side 256 → center-crop 224.
   • Convert to float32, normalise with µ=[0.485,0.456,0.406], σ=[0.229,0.224,0.225].
   • Permute to CHW, cast to bf16 before forward pass.
   Corruption is already baked into the image files by the dataloader – no run-time augmentation is allowed (§Protocol 3).

4. Data splitting / Repetitions
   Stream acts as a *test-only* set; no intra-stream validation.
   Seeds controlling: (i) global torch / numpy RNG, (ii) starting index offset (0, 5 000, 10 000).  We run N=3 seeds and report mean ± σ.  Because no training takes place, “best-val vs last” is moot – the *whole trajectory* is evaluated.

5. Hyper-parameters & Search (offline)
   CurvTrack grid (performed once on ImageNet-C 10-k dev set, *not* on ShiftTrack)
     – Block size G ∈ {4, 8, 16, 32}
     – α_max   ∈ {0.01, 0.05, 0.10}
     – EMA β   ∈ {0.90, 0.95, 0.99}
     – TinyCurvNet on/off, quant8 on/off
   Latin hyper-cube 3×4×3×2×2 ⇒ 144 runs (each 10 min on A100).  Best-val mCE chooses the tuple (G=16, α_max=0.05, β=0.99, TinyCurvNet=yes, quant8=yes) which is fixed for *all* reported numbers.

6. Evaluation metrics
   Primary
     • Online Top-1 accuracy (stream-wise mean)
     • Mean Corruption Error (mCE, implicit clean baseline = ImageNet-val)
     • Time-to-80 %-recovery (frames) after each corruption switch
   Secondary
     • Deadline-miss rate (%)
     • Mean latency per image (ms) and 95-th percentile latency
     • Energy / image (nJ) measured by NVIDIA-SMI sample-based ∆P·∆t integral
     • Peak GPU memory (MB) and extra parameter-update traffic (MB/s)
     • ECE (15-bin) for calibration insight

7. Robustness analysis within the same run
   • Inject artificial 8-bit JPEG compression *after* 130 k frames for 10 k frames to test out-of-spec distribution shift.  Log separate adaptation-lag.
   • During frames 200 k-210 k add i.i.d. pixel noise ε∼N(0,σ²), σ=4/255, and measure accuracy drop vs recovery.
   • Bit-flip: on frame 230 k zero out 1 % of CurvTrack’s low-rank vectors u_t (simulated SRAM failure) and track self-healing.

8. Complexity accounting
   FLOPs per image (forward only):
     – ResNet-50: 4.1 GF, ConvNeXt-T: 4.5 GF, ViT-B/16: 17.6 GF
   CurvTrack update add-on (per norm-layer block): 6C + 3C mul + 1C outer (rank-1) ≈ 16C where C=channels in block – totals: ResNet-50 0.19 GF (+4.6 %), ConvNeXt-T 0.23 GF (+5.1 %), ViT-B/16 0.44 GF (+2.5 %).
   Inference latency (A100, bf16, BS=32, cudnn-8.9):
     – static: 6.8 ms(Im) RS-50 → CurvTrack: 8.4 ms(+24 %)
     – Tent-3-step: 19.6 ms(+188 %)
   Memory: extra 4 × (#norm params) bytes = 174 MB (8-bit packed).  Tent needs activations ≈ 1.1 GB.
   Wall-clock cost: full 260 k-image run ≈ 715 s.

9. Implementation details (PyTorch 2.1)
   • Dataloader spawns 8 workers, pre-fetches 2 batches, pinned memory.
   • Gradient computation under CurvTrack is disabled globally (torch.set_grad_enabled(False)); TinyCurvNet forward is fused using torch.compile (nvFuser).
   • Quantised storage uses custom 8-bit log-float tensor with base-2 exponent and 3-bit mantissa (Köster 2020 format).
   • Whole experiment is scripted via Hydra; config yaml shown below.

```
# run_curvtrack.py
@hydra.main(config_path='conf', config_name='stress_a100')
def main(cfg):
    torch.cuda.set_device(0)
    model = timm.create_model(cfg.backbone, pretrained=True).eval().cuda()
    adaptor = CurvTrack(model, collect_norm_blocks(model, cfg.block_size),
                        alpha_max=cfg.alpha_max, ema=cfg.ema,
                        tiny_net=TinyCurvNet().cuda(), quant8=cfg.quant)
    stream = ShiftTrackLoader(cfg.data.root, batch_size=32, num_workers=8,
                              start_offset=cfg.seed*5000)
    meter = EnergyMeter(device=0)
    for i,(x,_,meta) in enumerate(stream):
        tic=time.perf_counter() ; meter.tick_start()
        x=x.cuda(non_blocking=True)
        with torch.autocast('cuda','bfloat16'):
            y = adaptor(x)
        meter.tick_stop(len(x))
        acc = top1(y, meta['label'])
        log_step(i,acc,time.perf_counter()-tic,meter.last_joules())
```

11. Comparison protocol adjustments (footnotes)
   *¹ CoTTA follows authors’ code but number of augmentations reduced from 10→4 to respect 33 ms deadline.  Pilot found <0.2 mCE difference.
   *² EATA default backlog buffer=64 is lowered to 32 to fit A100 L2; authors’ ablation shows negligible effect.

12. Expected results (mean ± σ over 3 seeds, ResNet-50)
   • Online Top-1 ↑ : 71.5 ± 0.3 %  (CurvTrack) vs 67.2 (FISHr) / 66.1 (NG-TENT) / 65.0 (Tent-3)
   • Time-to-80 %-rec ↓ : 90 ± 7 frames vs 430 / 510 / 610
   • Deadline-miss ↓ : 0.7 % vs 31.4 % (Tent-3), 17.9 % (CoTTA)
   • Energy / img ↓ : 11.6 mJ vs 19.4 mJ (FISHr) / 26.8 mJ (Tent-3)
   • mCE ↓ : 48.2 vs 52.7 / 55.1
   Similar trends hold for ConvNeXt-T (+3.8 mCE) and ViT-B/16 (+2.9 mCE).
