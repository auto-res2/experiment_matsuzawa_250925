# Experimental Design

## Experiment Strategy
Single-Pipeline, Multi-Granularity Benchmark

Goal: Show that S³-GAT simultaneously (i) removes the soft-max bottleneck, (ii) lowers memory & launch count, (iii) keeps statistical error within the analytic bound, and (iv) preserves accuracy.

1. End-to-End Training Benchmark
   a. Datasets & Models: OGBN-Arxiv (small), Reddit (mid), Products (large), Papers100M (huge) on 2-, 4- and 8-layer GAT variants.  Train 3 seeds each.
   b. Systems:  Single A100-80 GB; PyTorch 2.1 + Triton 2.1; identical dataloader & optimiser (AdamW, lr-schedule) for all runs.
   c. Runs:
      • FP32 dense GAT (upper-bound)
      • GATSY-X (state-of-the-art sparse/quantised)
      • S³-GAT (auto-tuned γ, τ)
   d. Metrics captured every epoch with torch.cuda.memory_stats() and Nsight-Sys counters:
      peak-memory, wall-clock, #kernel-launches, SM occupancy, dram-bytes, power draw.
      Stop when validation accuracy plateaus  (≤0.02 % change over 10 epochs).
   e. Expected outcome:  S³-GAT uses ≤20 % of FP32 memory, ≥1.5× faster than next best, identical final accuracy (≤0.3 %).

2. Component Ablation Sweep (Same hardware, Reddit dataset)
   For each mechanism {M1…M5} flip ON→OFF while keeping others ON.
   Log: memory, time/epoch, accuracy @20 epochs.
   Demonstrates which sub-modules deliver the gains; e.g. turning off M2 should raise useless-edge ratio by ≈7 % and hurt accuracy by ≈0.4 %.

3. Variance-Bound Verification (M3)
   During every 50th iteration record:  empirical var(êᵢ) over 2048 sampled nodes vs analytical bound γ·σ²_total.
   plot ratio; expect ≤1.1 across training, proving adaptive LSH achieves target error without hand-tuning.

4. Micro-benchmark of Streaming Prefix Soft-max (M1)
   Synthetic graph with controllable average degree k∈{32,64,128,256}.
   Time the sole soft-max kernel of S³-GAT vs cuDNN soft-max on pre-materialised logits.
   Measure latency and dram traffic via Nsight-Compute roofline.
   Expect ≥3× speed and memory proportional to B not k, confirming removal of O(k) normaliser reduction.

5. Quantisation Fidelity Study (M4)
   Collect 10⁶ (logit, δ) pairs during Reddit training.
   Compare INT4 differential vs plain INT4 & INT8 by computing KL divergence to FP16 distribution.
   Show 2× lower KL for differential INT4 → validates bit-efficiency claim.

6. Kernel Fusion Proof-of-Concept (M5)
   Use Triton trace-replay to count kernel launches in one forward pass.
   Baseline sparse pipelines show 4–6; S³-GAT shows exactly 1, with ≥80 % SM occupancy.

What the Results Demonstrate:
• End-to-end run confirms holistic efficiency (memory + speed + accuracy) over real graphs.
• Ablations pinpoint that gains truly stem from proposed ideas rather than implementation quirks.
• Variance experiment proves theoretical guarantee (M6) translates to practice.
• Micro-benchmark isolates the removal of the soft-max bottleneck (P1).
• Quantisation study validates smarter use of bits (P4).
• Kernel-fusion test highlights engineering contribution (P5), important for deployment.

Collectively, one coherent experimental pipeline validates that S³-GAT solves all six open problems P1–P6 on commodity hardware.

EXPERIMENT 1 – END-TO-END TRAINING BENCHMARK
------------------------------------------------------------
Goal: Validate (i)–(iv) of the Experiment Strategy in a realistic training setting.

1. Models
   • FP32-GAT-2L, FP32-GAT-4L, FP32-GAT-8L (Balanced-Init)
   • GATSY-X-4bit (author’s open-source release v1.3)
   • S³-GAT-2L / ‑4L / ‑8L (ours, INT4 differential, variance–adaptive)
   *All in the same PyTorch code base; the baseline GATSY-X kernel is imported as a Python extension to avoid implementation drift.*

2. Datasets
   • OGBN-Arxiv    (18 k nodes, 91 k edges)
   • Reddit        (233 k,    11 M)
   • OGBN-Products (2.5 M,   61 M)
   • OGBN-Papers100M (111 M, 1.6 B)
   Official OGB splits (train/val/test) are kept unmodified.  Zero-copy mmap is used for Papers100M to fit within 80 GB.

3. Pre-processing
   • Features: row-wise FP32 → FP16 cast; PCA-256 for Products & Papers100M to lower I/O; stored in CSR with uint32 indices.
   • Graph: remove self-loops; add reverse edge for undirected variant; sort by destination to improve CSR locality.
   • On-the-fly normalisation (sym-norm) performed inside first kernel launch.

4. Data splitting / batching
   • Mini-batching by GraphSAINT (node sampling) with fixed 30 k / 120 k / 500 k / 2 M nodes per batch (Arxiv…Papers).
   • 3 independent seeds {13, 17, 29}.  For every seed: run until val-accuracy does not improve by ≥0.02 % over 10 epochs OR 400 epochs max.

5. Optimiser & schedule
   AdamW, lr = 0.003, β = (0.9,0.999), weight-decay = 5 e-4.
   Cosine decay with 5-epoch warm-up.  Gradient clipping 1.0.
   S³-GAT additionally exposes γ∈[0.8,0.98] and τ_init∈[0.01,0.2]; auto-tuner chooses per-run values on the first 200 optimisation steps (held-out from epoch count).

6. Evaluation metrics / logging
   Primary: Final test Accuracy, Time-to-80 %-of-FP32 accuracy (T80), Peak GPU memory.
   Secondary: wall-clock per epoch, #kernel launches, SM occupancy, DRAM bytes, mean power.
   All metrics pulled every epoch via:
      • torch.cuda.memory_stats()
      • torch.profiler + Nsight-Sys (–gpu-metrics-device all –sampling-interval 500)

7. Selection criterion for reporting
   For each seed we report “best-val” checkpoint.  Final table shows mean ± std across 3 seeds.

8. Hyper-parameter analysis
   Learning-rate grid {0.001, 0.003, 0.01}; γ grid {0.85,0.9,0.95}; τ_pid_gain ∈{0.5,1.0,2.0} – explored by 24-run sweep on Reddit only; effects plotted as 3-D response surfaces of (speed, accuracy).

9. Robustness
   • Feature noise: add N(0,0.01) at inference-time, measure ΔAcc.
   • Structural noise: random 5 % edge deletions.
   • Distribution shift: test on the OGB out-of-time splits (products-2022 subset).  Record accuracy drop.
   • Adversarial (nettack – fast mode, 3 perturbations per node).  Report robust accuracy.

10. Efficiency statistics
   FLOPs counted by fvcore’s FlopCountAnalysis with custom patch for Triton kernels; memory footprint via pytorch-cuda-memory.
   Cost: wall-clock × $1.79/h (on-demand A100-80) – reported per epoch & full run.
